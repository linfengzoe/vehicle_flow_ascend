# 大作业报告大纲

建议报告题目：

> 基于昇腾开发板的 YOLO 车辆大类识别与单线车流统计系统

## 1. 选题背景与意义

可写内容：

- 城市道路、校园道路、停车场等场景需要统计车辆流量；
- 传统人工统计效率低，实时性差；
- 基于计算机视觉的车流统计可以自动识别车辆并统计数量；
- 将模型部署到昇腾开发板，可以体现边缘端实时推理能力，减少对云端服务的依赖。

建议强调：

- 本项目不是完整智能交通系统，而是导论级可落地闭环：车辆检测、分类、计数、部署、演示。

## 2. 系统需求分析

### 2.1 功能需求

- 支持本地视频、浏览器摄像头和开发板 USB 摄像头输入；
- 检测画面中的车辆；
- 将车辆分为 4 类：
  - 小型车 `car`；
  - 公交/客车 `bus`；
  - 货车 `truck`；
  - 两轮车 `two_wheeler`；
- 设置一条计数线；
- 当车辆穿过计数线时进行统计；
- 输出总车流量和分类车流量；
- 显示 FPS；
- 保存演示视频；
- 保存 H.264 MP4 演示视频并支持浏览器播放；
- 支持昇腾 OM 模型部署；
- 支持 HTTPS Web Dashboard 和一键启动脚本。

### 2.2 非功能需求

- 能够稳定运行 30 到 60 秒演示视频；
- 测试和配置可复现；
- PC 端和昇腾端复用同一套跟踪计数逻辑；
- 开发板 Web 后端能连续启动/停止推理任务；
- 默认测试不依赖真实模型权重和开发板环境。

## 4. 方法原理

### 4.1 YOLO 目标检测

可写内容：

- YOLO 是单阶段目标检测算法；
- 输入图像经过神经网络后输出目标框、置信度和类别概率；
- YOLOv5n 模型轻量，适合边缘端部署；
- 本项目使用检测框和类别结果作为后续计数基础。

### 4.2 图像预处理

- BGR 转 RGB；
- letterbox 等比例缩放和填充；
- 像素归一化到 `0..1`；
- HWC 转 NCHW；
- 固定输入尺寸 `1x3x640x640`。

### 4.3 后处理

- 根据 objectness 和类别概率计算置信度；
- 过滤低置信度目标；
- 将 `xywh` 转为 `xyxy`；
- 根据 letterbox 的 ratio 和 padding 还原到原图坐标；
- 执行 NMS 去除重叠框；
- 将 COCO 类别映射到项目车辆类别。

### 4.4 质心跟踪

- 对每个检测框计算中心点；
- 使用最近距离匹配当前帧检测和已有轨迹；
- 为每个车辆维护 `track_id`；
- 对短暂漏检设置 `max_disappeared` 容忍帧数。

### 4.5 单线穿越计数

- 计数线由两个点确定；
- 使用叉积判断点位于线的哪一侧；
- 当前后两帧中心点位于计数线两侧时，认为车辆穿线；
- 只对有限线段进行穿越判断；
- 每个 `track_id` 只计数一次，避免重复计数。

## 7. 昇腾部署流程

### 7.1 模型转换

```text
PyTorch .pt -> ONNX -> OM
```

对应脚本：

```bash
bash scripts/export_yolov5_to_onnx.sh
bash scripts/convert_onnx_to_om.sh
```

### 7.2 板端运行

```bash
source /usr/local/Ascend/ascend-toolkit/set_env.sh
PYTHONPATH=src:$PYTHONPATH python3 -m vehicle_flow_ascend --config configs/ascend_om.yaml
```

HTTPS Web 后端推荐使用一键脚本：

```bash
cd /home/HwHiAiUser/vehicle_flow_ascend_current
./scripts/start_devboard_web.sh
```

PC 浏览器访问：

```text
https://192.168.137.100:8766/
```

### 7.3 部署注意事项

- `soc_version` 要与开发板一致；
- 本项目按 Atlas 200I DK A2 默认使用 `Ascend310B4`；
- ONNX 输入尺寸固定；
- 注意 BGR/RGB 转换；
- 注意 letterbox 坐标还原；
- NMS 在 CPU 端执行；
- 先用本地 MP4 验证稳定性，再尝试摄像头；
- 远程访问浏览器摄像头必须使用 HTTPS；
- 开发板 USB 摄像头建议用 `root` 启动 Web 后端；
- Web 长进程内 Ascend ACL 只初始化一次，避免连续推理第二次启动时报 `acl.init failed with ACL error code 100002`；
- 开发板 Python 3.9 环境需要延迟类型注解，源码和测试已覆盖该兼容性。

## 8. 问题与改进

可写问题：

- 遮挡严重时质心跟踪可能 ID 切换；
- 远距离小目标容易漏检；
- 货车和公交有时可能混淆；
- 夜间、雨天、模糊视频效果下降；
- 计数线位置对计数准确率影响较大。
- 开发板摄像头识别效果受摄像头角度、车辆距离、光照和 COCO 预训练模型泛化能力影响。

改进方向：

- 使用更多本地道路数据微调模型；
- 从 YOLOv5n 升级到 YOLOv5s；
- 引入 ROI 区域过滤；
- 引入 ByteTrack/SORT；
- 增加双向计数；
- 尝试 INT8 量化提升昇腾端 FPS。
